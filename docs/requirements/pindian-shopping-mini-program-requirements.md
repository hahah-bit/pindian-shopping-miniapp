# 拼单购物微信小程序需求文档

## 1. 项目概述

开发一个微信小程序拼单购物平台。管理员在后台发布商品，用户按照商品份额参与拼单并立即支付对应金额。当一个拼单组内的用户份额总和达到 1 时，该拼单组成功。一个商品可以根据库存连续生成多个拼单组。

商品拼单成功后，按照每位用户购买的份额拆分商品并分别发货。平台同时提供自建客服系统，支持在线实时聊天和离线留言。

## 2. 已确认的业务规则

### 2.1 份额选项

用户可选择以下份额：

- 1/2
- 1/3
- 1/4
- 1/5

管理员可以为商品配置允许使用的份额选项。

### 2.2 拼单成功条件

同一个拼单组内的所有有效订单份额之和等于 1 时，拼单成功。

建议使用 60 作为基础份额单位，避免小数计算误差：

| 用户选择 | 占用单位 |
| --- | ---: |
| 1/2 | 30 |
| 1/3 | 20 |
| 1/4 | 15 |
| 1/5 | 12 |

拼单成功条件为当前拼单组累计达到 60 个单位。

### 2.3 商品可以连续生成多个拼单组

一个商品不限制只能拼成一组。商品库存充足时，可以连续生成多个独立拼单组。

示例：

```text
商品 A
├─ 拼单组 001：已成功，进入履约
├─ 拼单组 002：进行中
├─ 拼单组 003：进行中
└─ 后续拼单组：根据库存自动创建
```

每个拼单组独立管理参与用户、订单、截止时间、支付、退款和履约状态。

### 2.4 系统自动匹配

用户只选择商品和份额，不手动选择拼单组。

系统匹配规则：

1. 优先查找当前商品中已有的可匹配拼单组。
2. 优先匹配最接近拼满且加入后仍可完成的拼单组。
3. 加入后不能超过完整商品份额。
4. 加入后剩余份额必须仍能由允许的份额组合完成。
5. 没有合适的拼单组时，自动创建新的拼单组。

系统必须避免形成无法拼满的组合。例如，`1/2 + 1/3 = 5/6`，剩余 `1/6` 不在可购买选项内，因此不能允许该组合进入死组状态。

### 2.5 用户端价格

管理员设置整件商品价格 `P`，平台固定增加 5 元服务费：

```text
用户端整件价格 = P + 5 元平台服务费
用户应付金额 = (P + 5 元) × 用户份额
```

示例：管理员设置整件价格为 500 元：

| 份额 | 用户端支付金额 |
| --- | ---: |
| 1/2 | 252.50 元 |
| 1/3 | 168.33 元或 168.34 元 |
| 1/4 | 126.25 元 |
| 1/5 | 101.00 元 |

金额统一以“分”为最小单位保存。不能整除时，前面的订单按规则计算，最后一个完成拼单的订单自动补差额，使整组订单金额合计严格等于用户端整件价格。

平台服务费需要在后台单独记录，但用户看到的是包含服务费后的最终份额价格。

### 2.6 运费

当前需求不单独收取运费。用户订单金额只包含商品份额金额和平台 5 元服务费对应的份额金额。

### 2.7 支付和份额锁定

用户选择份额后立即支付对应金额。

流程：

```text
提交订单
→ 临时锁定份额
→ 调起微信支付
→ 支付成功：份额正式生效
→ 超时未支付或支付失败：释放份额
```

未支付订单的份额锁定时间需要后台可配置，建议初始值为 10 分钟。

支付回调必须支持重复通知，避免重复记账、重复占用份额或重复处理订单。

### 2.8 用户主动取消

拼单成功前，用户可以主动取消订单。

取消流程：

```text
用户取消
→ 订单状态变为已取消
→ 释放用户占用的份额
→ 拼单组累计份额同步减少
→ 退款商品份额金额
→ 退款平台服务费
→ 用户全额退款
```

例如用户实际支付 126.25 元，取消后退款金额仍为 126.25 元。

限制：

- 拼单成功前允许主动取消。
- 拼单成功后不能直接取消，需通过售后工单处理。
- 已进入拆分或发货流程后不能直接取消，需通过售后处理。
- 取消后系统重新判断拼单组状态和可完成性。
- 如果取消导致拼单组从已成功变为不足 1，应在进入正式拆分发货前恢复为进行中。

### 2.9 拼单失败和退款

拼单达到截止时间仍未达到 1 时：

- 拼单组变为“拼单失败”。
- 所有有效支付订单进入退款流程。
- 按用户实际支付金额全额退款，包含平台服务费对应金额。
- 用户可以查看退款状态。
- 管理员可以查看退款异常并重试。

退款记录至少保存：退款单号、退款金额、退款状态、申请时间、完成时间、失败原因和处理日志。

## 3. 用户端功能

### 3.1 登录和个人信息

- 微信授权登录。
- 绑定手机号。
- 管理收货地址。
- 查看个人订单和退款记录。

### 3.2 商品列表

展示：

- 商品主图。
- 商品名称。
- 用户端价格或份额起售价。
- 当前拼单进度。
- 剩余库存。
- 商品状态。

### 3.3 商品详情

展示：

- 商品图片和详情。
- 整件商品数量及计量单位。
- 管理员设置的商品原始价格对应的用户端最终价格。
- 可购买份额。
- 每种份额对应的实际数量。
- 当前拼单进度。
- 拼单截止时间。
- 发货说明和售后说明。
- 联系客服入口。

### 3.4 下单支付

- 选择份额。
- 选择或新增收货地址。
- 确认商品份额金额。
- 确认平台服务费对应金额。
- 确认实际支付金额。
- 提交订单并调用微信支付。
- 支付成功后查看拼单状态。

### 3.5 拼单详情

用户可以查看：

- 拼单组编号。
- 当前已完成份额。
- 剩余份额。
- 同组参与人数。
- 拼单截止时间。
- 拼单状态。
- 联系客服入口。

### 3.6 我的订单

订单状态包括：

```text
待支付

已支付
拼单中
拼单成功
待发货
已发货
已完成
已取消
拼单失败
退款中
已退款
退款失败
```

## 4. 商品和库存管理

管理员发布商品时需要填写：

- 商品名称。
- 商品主图、详情图和图文详情。
- 商品介绍。
- 整件商品价格。
- 整件商品数量。
- 计量单位，例如斤、克、件、箱、份等。
- 每种份额对应的实际数量。
- 是否允许小数数量。
- 完整商品库存。
- 可用份额选项。
- 拼单截止时间。
- 发货时效。
- 商品售后说明。

商品状态：

```text
草稿
待上架
进行中
已下架
已售罄
已结束
```

库存需要区分：

- 商品总库存。
- 已创建拼单组数量。
- 进行中的拼单组数量。
- 已成功拼单组数量。
- 剩余可售完整商品数。

## 5. 分份履约和发货

拼单成功后，商品按照每位用户购买的份额拆分，分别发给每位用户。

示例：

```text
拼单组 001
├─ 用户 A：购买 1/2，获得 5 斤，独立快递单
├─ 用户 B：购买 1/4，获得 2.5 斤，独立快递单
└─ 用户 C：购买 1/4，获得 2.5 斤，独立快递单
```

管理员可以：

- 查看每位用户应得的数量。
- 查看用户收货信息。
- 为每位用户单独填写快递公司和运单号。
- 批量导出发货单。
- 单独标记已发货和已完成。
- 单独处理补发、售后和异常。

一个拼单组可以部分发货，系统需要分别统计每位用户的履约状态。

## 6. 管理后台功能

### 6.1 管理员和权限

角色建议包括：

- 超级管理员：全部权限。
- 商品管理员：商品、库存和商品上下架。
- 订单管理员：订单、拼单组和履约。
- 财务人员：支付、退款和财务数据。
- 客服主管：客服分配、工单和客服数据。
- 客服人员：处理分配到的会话和工单。

### 6.2 商品管理

- 新增、编辑、查看和下架商品。
- 上传商品图片和详情。
- 配置价格、平台服务费、库存和份额。
- 配置拼单截止时间。
- 查看商品的所有拼单组。

### 6.3 拼单组管理

查看：

- 拼单组编号。
- 所属商品。
- 当前参与人数。
- 已完成份额。
- 剩余份额。
- 参与订单。
- 创建时间和截止时间。
- 支付状态。
- 拼单状态。
- 发货状态。

拼单组状态：

```text
进行中
已拼满
拼单成功
拼单失败
退款中
已关闭
已完成
```

### 6.4 订单、支付和退款管理

- 按时间、商品、用户和状态查询订单。
- 查看商品金额、平台服务费和实际支付金额。
- 查看支付记录和微信支付单号。
- 发起或审核人工退款。
- 查看退款状态和失败原因。
- 对异常退款进行重试。
- 导出订单和退款数据。

### 6.5 履约管理

- 查看待拆分发货拼单组。
- 查看每个用户应得的份额数量。
- 批量导出发货单。
- 录入快递公司和运单号。
- 查看待发货、部分发货和已完成发货数据。

## 7. 自建客服系统

客服模式：

- 客服在线时实时聊天。
- 客服离线时自动转为留言。
- 用户重新进入时可以继续查看历史会话。

### 7.1 用户端客服

支持发送：

- 文字。
- 图片。
- 商品卡片。
- 订单卡片。
- 拼单组卡片。
- 退款记录卡片。

第一版暂不支持语音、视频和文件传输。

### 7.2 客服后台

客服可以：

- 查看待接入会话。
- 接入和结束会话。
- 实时回复用户。
- 查看用户信息、订单、拼单、支付和退款状态。
- 转接其他客服。
- 添加内部备注。
- 将会话转为售后工单。
- 查看历史聊天记录。

会话状态：

```text
排队中
接待中
待用户回复
待客服回复
已结束
已转工单
```

### 7.3 售后工单

工单类型：

- 拼单问题。
- 支付问题。
- 退款问题。
- 商品问题。
- 发货问题。
- 投诉建议。
- 其他问题。

工单状态：

```text
待处理
处理中
等待用户反馈
已解决
已关闭
```

工单应关联用户、商品、拼单组、订单和退款记录。

### 7.4 客服分配

- 新会话进入公共队列。
- 自动分配给在线且当前接待量较少的客服。
- 客服离线时允许用户留言。
- 客服上线后处理留言。
- 超过设定时间未回复时提醒客服主管。

## 10. 异常和安全要求

系统需要处理：

- 多人同时购买最后份额。
- 支付成功但订单状态未更新。
- 支付回调重复通知。
- 订单重复提交。
- 份额锁定超时。
- 用户取消后拼单组份额变化。
- 拼单截止和用户支付同时发生。
- 拼单失败退款失败。
- 客服消息发送失败或 WebSocket 断线。
- 商品下架但已有用户支付。
- 管理员重复点击发货或退款。

系统还需要：

- 事务和并发控制，防止份额超卖。
- 支付、退款和状态变更幂等处理。
- 管理员操作日志。
- 手机号、地址等敏感信息脱敏。
- 用户协议和隐私政策。
- 客服消息和用户数据访问权限控制。
