# 备份恢复与健康检查 spec

依据：[大任务规范](../../tasks/T012-release-readiness/spec.md)；用户授权本地/模拟范围。

备份 PG 与媒体生成清单及校验摘要，恢复仅指定隔离目标，禁止覆盖当前源项目；备份前暂停 API/Worker 写入，结束恢复原运行状态。核对业务数据与媒体哈希；检查 API/Worker/PG。不记录密钥或连接密码。

验收：目标隔离与恢复前校验采用 TDD；真实备份→新隔离项目恢复→核对事实与媒体，不能以文件存在代替恢复。 失败保持明确错误与未完成；既有公共 API、权限与金额单位不变。待决策：无本地实现阻塞；真实环境单列待验。


## 备份与恢复契约（实现前）
backup CLI 接收源项目/环境文件与新输出目录，暂停原来运行的API/Worker，在一致窗口pg_dump custom + tar媒体 + 业务表数量/行摘要 + schema_migrations；finally恢复原运行状态。manifest v1只记录项目、时间、两个文件SHA256、业务摘要与迁移名，不记录密码/连接串。恢复CLI只接受新pindian-rehearsal-restore-*目标（不可等于源），Docker容器/卷已存在也拒绝；验证文件摘要后才建目标。pg_restore失败退出；仅新卷解包媒体，核对数据库事实及文件摘要后启动服务。生产恢复交接要求以新项目名称和切换流量方式进行，不自动覆盖生产库。
健康CLI综合docker健康/API请求/Worker心跳，异常退出非零。

模拟演练补充：rehearsal模式也暂停simulator并备份其独立虚拟交易状态（simulator.tar），恢复后旧支付/退款查单仍可用；仅本地虚拟事实，不包含密钥，不增加生产外部渠道备份。manifest允许此第三个固定文件名，其摘要同样在任何目标修改前验证。生产备份仍为PG+媒体，真实渠道事实由微信持有。
