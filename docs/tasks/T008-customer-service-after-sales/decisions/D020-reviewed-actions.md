# D020 售后退款与补发审批（2026-10-02 已确认）

来源：用户明确选择“客服申请，超级管理员审核后执行全额退款或补发（推荐）”。覆盖 D017 原未答复的“不新增审批层”建议；数量异常采用已确认 D019。

客服、主管和超级管理员均可提交所属工单的处理申请；仅超级管理员可以审核。退款和补发申请与渠道退款/包裹事实分离：申请不产生退款/发货，审核通过才通过公开用例创建业务事实，退款到账仍依渠道证据。拒绝保留原因，可另行申请，不修改原申请。

售后退款针对成功或失败组的本人已生效支付订单，按实付全额（含服务费），不允许超退或再退已有退款支付。进行中组沿用已确认取消流程，不借售后审批回退成功组或修改份额。批准退款停止该订单后续新增履约/包裹，保留已发货事实与成功组、订单数量和价格快照。补发复用 D013，原因必填，不改变原发货数量和状态；已批准全额退款订单不再补发。上述边界是本审批功能为交易闭环采用的实施规则，不新增部分退款。

历史零分配组提供按已支付订单提交审批入口，仍由超级管理员逐单审核，全额依据支付事实；不能修改历史数量后强行履约。任一数据库、工单 action 或审计失败时，申请审核结果和退款/补发/履约停止记录共同回滚；同申请重复审核只创建一次事实。
