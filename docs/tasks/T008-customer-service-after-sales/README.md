# T008 自建实时客服与售后工单

- **编号**：T008（唯一；现有功能至 F030、任务至 T007、迁移至 0017）；子功能 F031–F035。
- **目标**：自建客服系统——用户发送文字/图片/商品/订单/拼单/退款卡片，客服后台接入/回复/转接/备注/转工单；新会话入公共队列自动分配在线客服；离线自动转留言；历史分页与断线补取；售后工单受理/处理/解决/关闭，可经公开用例协调退款/补发。第一版不含语音/视频/文件/AI 回复。
- **主领域**：CustomerService（会话与消息）、AfterSales（工单）；协作：IdentityAccess（用户/客服身份）、Catalog/Ordering/GroupBuying/Payments（卡片只读投影）、Audit。
- **前置**：T003（用户身份）、T006（退款事实）、T007（履约事实）。
- **当前状态**：验证中——实现与自测完成（2026-10-02：专项 14/14、全量 224/224、Docker 迁移 0018、有数据后台接入交互通过）；待独立复验。D017/D018 为建议方案（征询未答复）。
- **阻塞项**：无阻塞实现的未决项——消息传输方式已定为**HTTP 轮询拉取**（设计结论，见 D016）；售后处理流程/时限按建议方案（D017/D018）推进并在实现前如实标注待确认。

## 工作决策

| 编号 | 议题 | 决策 | 状态 |
| --- | --- | --- | --- |
| D016 | 实时传输方式 | **HTTP 轮询拉取**（长轮询语义：客户端每 2s GET 新消息 cursor 参数；服务端消息持久化+seq 单调，断线按 cursor 补取）。消息持久化、确认（seq 已读位点）、顺序（组内 seq 严格递增）、幂等（clientMessageId 去重）先于传输方式设计 | 设计结论（2026-10-02） |
| D017 | 售后处理流程 | 管理员处理+用户反馈：工单提交→管理员受理/处理（可发起全额退款/补发，资格与额度由支付/履约公开用例校验）→用户确认解决或管理员关闭；不新增审批层 | 建议方案（征询未答复，2026-10-02） |
| D018 | 处理时限 | 第一版不做超时提醒/自动升级；异常统计计数待处理工单 | 建议方案（征询未答复，2026-10-02） |
