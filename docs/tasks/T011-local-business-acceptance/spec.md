# 两端交互与完整业务验收规范

依据：用户 2026-10-02 授权四阶段连续执行；保留 D015/D019/D020/D021。范围：本地真实后端、真实 PG 和 Worker，微信使用隔离模拟；非目标：T005、真实付款、订阅消息外发、体验版上传与公网部署。

## AC1 小程序页面交互测试

Node 装置编译并加载实际 TS 页面，以 Page/setData/wx 适配驱动生命周期与点击；HTTP 请求真实本地后端。wx 登录/支付来自模拟渠道；wx 成功回调不能直接判订单已支付。验证权限、加载、空态、失败、取消、刷新和消息已读。

Given 独立环境已就绪，When 执行本功能，Then 满足上述行为及 不采用 TDD（测试装置/页面装配），实现后冒烟实际页面；微信渲染与真机单列待验。。

## AC2 跨模块完整业务验收

独立库、测试用户和管理员经 HTTP 跑商品→拼单→支付→履约→客服工单→审核退款/补发→通知看板审计。启动真实 Worker，验证中断后补偿恢复，避免在测试直接调用任务代替进程。复用 D015/D019/D020；使用 HTTP 操作形成业务事实，故障/时间探针仅限隔离测试库。

Given 独立环境已就绪，When 执行本功能，Then 满足上述行为及 TDD 用于发现的缺陷；新增验收装置后验证成功、取消/过期/失败、权限、尾差、部分发货、退款补发、Worker 重启。。


## 契约与页面

业务 API 复用 T003/T004/T006/T007/T008/T009 spec：Bearer 认证、后台权限、ApiResponse 包络、分页、整数分、ISO 时间、幂等规则不变。新增内容仅本地装置/配置/脚本。小程序与后台保留正常/加载/空数据/失败/权限状态；页面逻辑测试不等同微信渲染。模拟控制面具体字段与失败契约在对应子功能 spec 定义后实现。

## 验收

AC3：专项→全量→隔离整体冒烟均通过，无失败无跳过。AC4：每个功能有中文提交和 verification，保留其他未提交文件；真实渠道与真机单列待验。

异常：装置/进程失败退出非零，清理只限本任务创建资源；保留诊断但不打印密钥。涉及业务缺陷先修订 DDD/spec/plan，再回归测试先红后绿。
