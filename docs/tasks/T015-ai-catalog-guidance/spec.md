# T015 规范

依据：用户截图“有推荐的咖啡么”得到无法推荐的答复，以及当前开发授权。延续灰白蓝、精灵及文字对话；无支付、语音或新模型供应商。

行为：推荐咖啡/介绍某款/描述想买的类别时调用Pi只读search_catalog；一般地址/订单操作问答不附随机商品。没有匹配就诚实说明并引导商品搜索/人工，不臆造口味、销量、评价、优惠或执行结果。先取事实再介绍，模型不提供可点击外部URL。

工具契约：name=search_catalog；intent必填为product_recommendation或product_introduction；keyword必填string≤60（宽推荐可空）；category可选fruit/snack/drink/other。模型自动解析中文类别，预算只用于说明，当前未新增价格过滤，不声称严格按预算筛选。SDK schema与端口再次校验，拒绝额外参数/写工具。每条≤2次工具、≤3次模型请求，查询错误返回安全描述，不向模型传SQL/凭据。

分类词与名称搜索分开：精确水果/水果商品/fruit、零食/零食商品/snack、饮品/饮料/饮品商品/drink、其他/其他商品/other在无分类或同分类时规范为该分类+空名称词；有显式矛盾分类时保留原条件。普通具体名称、未知关键词不转换，不因没有结果而退化成全目录推荐。AC01补充：用户问当前水果/零食分类时，应返回该分类公开可用产品，而不是要求商品名称含“水果/零食”。模型选择推荐或介绍均能导购，介绍具体商品采用介绍意图。

旧轮次仅为对话上下文，不是当前商品证据；每次产品需求重新查询，不沿用历史“查不到/不可推荐”结论。Pi传给模型的历史助手消息须显式标为历史与非实时事实，系统提示再次要求重新检索；真实反复同问也单独复验。

公开API仍GET/POST /api/mini/v1/ai-support/messages，Bearer本人；POST UUID/text≤1000/原幂等语义，返回200；原401/400/404/409/429/502/503/504保持。AiSupportTurn新增intent enum（一般/推荐/介绍），recommendations≤3的数组，项{productId UUID,name string,imageUrl string|null,description string≤600,priceFromFen非负安全整数分}。旧历史填general/[]；无额外公开接口。时间ISO，游标本人UUID，金额仅参考份额价，不作为应付报价。

小程序：回复下显示真实图片、名称、参考价和“查看商品”；图片错误有占位、正文长名称换行，卡片≥96rpx触摸高。仅ID白名单+固定本项目商品详情路由，不解析任意URL。卡片恢复随本人历史/重放，已下架后详情既有404界面正常；缓存Tab及旧回调隔离沿T014。

- AC01 Given询问推荐咖啡/介绍产品，When识别工具并检索，Then仅显示匹配的公开可用商品卡片与有效固定详情入口；一般地址问答无推荐。
- AC02 Given草稿/下架/售罄/查询中失效/无匹配，When检索，Then不推荐不合法候选、无匹配不填无关商品；无未经依据的价格。
- AC03 Given模型尝试写工具、畸形参数、注入型描述或循环调用，When执行，Then只有公开读取，权限/次数/时间有硬上限，卡片不能由模型URL/ID伪造。
- AC04 Given完成/重放/分页/重启/旧租约迟到，When读取轮次，Then文本与卡片同次完成、旧执行不覆盖，历史快照不受当前改价污染，别人的轮次不可读。
- AC05 Given原生客服正常/空推荐/多图失败/长名称/发送失败，When阅读或点击，Then视觉与状态正确且进入实际详情；真实DeepSeek与受控模型测试分开。
- AC06 专项→全量通过，真实本地API/PG/Pi联调及原生页面检查；安卓真机/系统偏好/支付到账未验不记录为通过。
