# D-005 支付边界（本阶段保留，不实现）

状态：**边界声明（无需澄清即可按此执行）**。关联：任务授权"本阶段不接入真实微信支付与退款"。

## 本阶段做什么

1. **领域上实现"支付生效"内部用例**（`MarkOrderPaid`）：预占 → 已支付的单位转换（不重复占容量），触发组满判定（60 单位 → 组 success → 库存消耗）。该用例仅暴露给内部应用层协作（为 Payments 上下文预留的已定义接口），**不注册任何 HTTP 端点**，不对小程序/后台暴露。
2. 测试通过支付端口替身（fake 内部调用）驱动该路径，验证领域行为——替身只用于测试装配，不冒充真实微信支付验证。
3. 订单状态机包含 `unpaid → paid`，但生产环境本阶段订单只能停留在 `unpaid`（及 `cancelled`）。

## 本阶段不做什么（保留到支付阶段）

- 未支付订单到期自动取消：**做**（预占过期释放，订单置 `cancelled`）——这不是支付行为。
- 真实微信支付调起、支付回调、退款、迟到支付补偿：**不做**。
- 成功后取消（需退款）：**不做**；已支付订单无取消入口。
- 支付与过期竞争的补偿（迟到支付已付款待退）：**不做**；本阶段 markPaid 对过期预占直接拒绝并记录（测试覆盖），真实场景的已付款待退属支付阶段。
- 任何"标记已支付"的未鉴权接口：**不提供**。

## 用户可见的支付状态

小程序订单列表/详情明确显示"微信支付暂未开放，订单将在支付功能上线后可支付"——未支付订单绝不可能被展示为已付款或拼单成功。
