# D-004 时间参数与数量精度

状态：**已确认（2026-09-30 用户选定推荐值：预占 15 分钟、截止商品可配默认 24h）**。关联：需求文档 §2.7/§13。

## 推荐参数

| 参数 | 推荐值 | 替代值 | 说明 |
| --- | --- | --- | --- |
| 预占有效期 | **15 分钟** | 10 分钟（需求建议初始值） | 覆盖确认报价→调起支付链路；`ORDER_RESERVATION_TTL_MINUTES` 可配置；过期判定一律后端时间 `expires_at < now()` |
| 拼单截止时间 | **商品可配，默认 24 小时** | 全局固定 24h | 需求 §4 要求管理员填写"拼单截止时间"——T002 商品表单增加"截止小时数"字段（1–168h，默认 24）；组创建时 `deadline = now + hours`，写入组快照 |
| 过期判定口径 | 全部以后端 DB 时间为准 | — | 预占过期 = `expires_at < now()`；组截止 = `deadline < now()`；到期任务周期扫描（Worker，默认 30s），服务重启自动恢复（状态在 DB，无内存定时器依赖） |
| 数量精度 | 展示沿用 T002 参考舍入（≤3 位小数 half-up），**明确标注"参考数量"** | — | 最终履约拆分数量与舍入规则属履约阶段；本阶段任何接口不声称参考数量为履约数量 |

## 过期与截止的竞争口径

- 预占支付生效（内部 markPaid）前再次校验 `expires_at > now()`，过期即拒绝（本阶段表现为预占失效，真实迟到支付处理属支付阶段）。
- 截止瞬间下单/支付：以**事务开始时的 DB 时间**为准——deadline 已过则拒绝预占/生效，未过则允许完成；不引入额外缓冲窗口。

## 影响

- 商品表新增 `group_deadline_hours`（迁移增量字段，默认 24）。
- Worker 增加到期任务：预占过期释放（按 status 条件幂等）+ 组截止判定与库存释放（D-002）。
