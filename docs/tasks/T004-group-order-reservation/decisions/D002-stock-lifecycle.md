# D-002 整件库存生命周期

状态：**已确认（2026-09-30 用户选定方案 A）**。关联：需求文档 §2.3/§4、AGENTS §8。

## 背景

一个拼单组对应一整件商品。组创建、拼单成功、拼单失败、预占过期时，整件库存在 available（可售）/ reserved（被组占用）/ consumed（已售出）之间流转。T002 库存表已预留 `reserved_whole_items` 字段（恒 0）。

## 方案 A（推荐）：建组预留、成功消耗、失败/截止释放

状态流转（每次流转一条 stock_movement 记录，条件更新 + 幂等）：

| 事件 | available | reserved | 说明 |
| --- | --- | --- | --- |
| 创建组（事务内） | −1 | +1 | 组与预留同事务，任一失败整体回滚；库存不足（available=0）拒绝建组 |
| 组拼满成功（第 60 单位生效） | 0 | −1 | reserved → consumed（售出），available 不再变化 |
| 组截止失败 | +1 | −1 | reserved → available，释放回可售 |
| 组取消（无已支付时解散，本阶段仅内部用） | +1 | −1 | 同上 |

- **空组**：不自动解散——建组即设置截止时间（见 D-004），截止前空组持续作为可加入候选，占用 1 个预留整件；到期失败自然释放。
- **预占全部过期**：组回 open，仍占用预留，等待新买家或截止。
- **防重复释放**：组状态机 `open → success | failed` 单向；释放 SQL 条件更新 `WHERE status='open' AND deadline < now()`，到期任务重复执行以状态为条件天然幂等；`stock_movements` 按 `(product_id, reason_key)`（如 `group-release:{groupId}`）唯一约束防重。
- **竞争证明**：并发建组用行锁条件更新 `UPDATE stocks SET available=available-1, reserved=reserved+1 WHERE product_id=$1 AND available>0`，受影响行数=0 即拒绝；集成测试并发 N 建组验证 reserved 合计 ≤ 初始库存。

**案例**：库存 2 件。并发 3 个"无合适组可加入"的下单 → 恰好 2 个建组成功各预留 1 件（reserved=2，available=0），第 3 个建组失败返回库存不足。其中一个组拼满 → 该件 consumed；另一组截止 → 释放回 available=1。

## 方案 B（替代）：下单时预留整件、组取消时归还

每笔订单预占同时预留整件份额（非整件）。问题：份额容量已由组内 60 单位约束保护，整件粒度再预留会造成"组内 1 单位预占锁死 1 整件"之外的额外语义混乱，且需求 §4 明确"库存需要区分已创建拼单组数量"——组与整件一一对应更贴合。**不推荐**。

## 影响

方案 A 影响：Stock 聚合新增 consumed 统计口径；建组、组成功、组失败三处接入库存流转；到期任务需处理"组截止→释放库存"。
