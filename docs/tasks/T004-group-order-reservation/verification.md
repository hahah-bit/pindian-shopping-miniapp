## 集成覆盖的关键路径（真实 PG + 真实 HTTP）

建组+首单标准价+库存预留（3→2/0→1）· 幂等同键同内容返回原单（计数 1）/异内容 409 · 越权地址 404、越权订单 404（含随机 UUID 探针）· 三连 1/3 填满（reserved 60、paid 0、Σ报价 ≤ 整件价）· 满 60 组不可加入 → 建组2（2→1）· **并发最后份额：恰一人加入组C（occ 60），另一人建组失败 STOCK_INSUFFICIENT（库存 0 不超卖）** · 取消释放容量（60→30）· 到期任务（processed≥1、重复 processed=0）· 后台订单/组查询脱敏（JSON 无手机号/地址原文）· 组内成员摘要字段恰为订单号/昵称/单位/状态。

## 修复记录（过程中发现并修复）

1. DI 字符串 'CLOCK' 与 Symbol token 不匹配 → useExisting 别名。
2. 错误过滤器缺 T003/T004 错误码映射（IDEMPOTENCY_CONFLICT/SHARE_CAPACITY_CONFLICT/STOCK_INSUFFICIENT 等）→ 补全。
3. `user:manage`/`order:manage` 只加 contracts 未加后端角色集 → ROLE_PERMISSIONS 补齐。
4. 并发设默认/最后份额死锁与重复扣减 → 事务边界重审（设默认锁 users 行；建组整件预留为独立条件更新）。
5. **D001 边界修订**（实现期发现）：立即支付模式下最后单出现时其他订单通常未支付（paid 合计=0），原补差公式会得出 50500 错误报价 → 修订为"补差仅当组内其他单位全部已生效；否则标准价；零头对账属支付阶段"。**该修订待用户复核**。
6. dist 陈旧导致装饰器丢失（place/get 先后 401）→ 强制全量重编译；此后每次改后端均完整 build。
7. 归属 401→404 语义（不泄露订单存在性）。
8. 集成测试造数误用主库连接 → 改测试库连接 + 主库精确清理。
