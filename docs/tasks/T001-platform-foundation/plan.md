# T001 实施计划

依据：[spec](spec.md)、[DDD](ddd.md)、[整体架构](../../architecture.md)。先写 spec，后落本计划，再进入实现。

## 测试策略

本轮各子功能不采用 TDD：以框架装配、只读元数据和展示为主，没有交易规则。实现后验证关键成功/故障路径，不编写镜像式页面测试。后续金额、库存和退款默认 TDD。

专项入口 `npm run test:task:t001`：对纯就绪用例、启动失败配置、真实 HTTP/数据库不可达路径、前端请求适配及架构边界进行测试；`npm run smoke:docker` 实际验证容器、ready 和 Nginx 代理。全量入口 `npm test`：先类型检查和构建，再运行全部项目自动化测试和架构检查。全量现阶段主要为 T001 测试，未来新增测试自动纳入；不伪造历史回归覆盖。

Docker 验证前提：本机 Docker Linux 引擎可用、可下载基础镜像、默认 3000/8080/5433 端口未被占用。因本机 5432 已有 PostgreSQL，当前宿主数据库端口改为 5433；专项同时验证容器内部和本机连接，不停止原服务。小程序本轮执行 TypeScript 检查和原生配置验证；开发者工具、微信身份、支付、真机未验证时明确记录。
