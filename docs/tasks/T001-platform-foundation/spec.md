# T001 功能规范

## 目标与范围

建立 TypeScript 工程、六边形目录边界、可独立构建的两个前端和后端、健康与平台元数据契约、Worker 入口及 Docker Compose。业务 MVP 完整范围保留，但本任务不实现登录、商品增删、下单、真实支付、退款、消息聊天或持久化业务任务。

## 场景与验收条件

- AC01：安装依赖后，contracts、backend、admin 均可构建，小程序可通过类型检查；锁文件可用于 `npm ci`。
- AC02：后端启动后 live 返回 200；无数据库时 live 仍成功，ready 返回 503；错误无连接凭据或调用栈。
- AC03：数据库实际可达时 ready 返回 200，并带 requestId；HTTP 未知路径返回结构化 404。
- AC04：用户和管理平台元数据符合公开契约，各业务上下文为 planned，未认证接口不包含业务数据。
- AC05：后台有全部业务导航、mock/真实来源标识、加载及错误反馈；框架页能经代理读取平台元数据，其他页面明确未实现。
- AC06：原生小程序有商品、订单、我的入口、feature 目录和 API/Mock 切换；可以导入开发者工具，类型检查不替代真机验收。
- AC07：Compose 配置可解析，核心四服务可构建并健康启动；数据库命名卷及 localhost 端口绑定有效，后台 `/api` 代理可用。
- AC08：Worker 启动并检查数据库，健康记录有时效；不执行或宣称完成任何退款和到期任务。
- AC09：源码架构检查拒绝 domain/application 导入 NestJS、pg 或 adapters，契约和客户端不导入 backend 内部实现。
- AC10：专项测试通过后执行项目全量测试；保留命令、环境、实际结果及未覆盖事项。

Given 数据库不可达，When 客户端查询 ready，Then HTTP 503 且 live 仍可响应。

Given 管理后台在 Docker 中运行，When 打开框架概览，Then 浏览器使用同源 `/api` 并获得后端元数据，无需解析容器名。

Given 业务模块只有目录边界，When 客户端查看模块状态，Then 显示“已规划”，不能展示为“已实现”。

## 契约与环境

公开接口参照 `contracts/openapi.yaml`；GET 接口只读，无幂等写入需求。requestId 贯穿正常/错误响应；ready 为 200 或 503。接口不接受密钥、支付金额或业务状态输入。服务器时间 ISO 8601 UTC，界面按用户时区展示。

Node 24 主版本；数据库、端口和允许跨域来源通过环境变量配置并检查。错误配置应拒绝启动。Docker 为本地联调，默认无公网数据库端口、无真实微信配置。appId 使用 touristappid 占位，不声称验证微信授权能力。

## 前端设计与待决策

后台为侧栏 + 内容区 + 模块状态卡片；小程序三个主入口和轻量框架说明。真实数据来源失败应显示错误，不自动伪装成成功 mock。业务所需尾差、取消、库存生命周期等争议不影响本轮骨架，但必须在后续 spec 解决。
