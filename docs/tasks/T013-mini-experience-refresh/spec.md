# T013 整体规范

依据：2026-10-06 用户明确开发请求、Pi 项目内对话内核确认、直接实施 UI 确认。延续 AGENTS.md 与既有业务规则。目标是可操作的自用小程序；不包括上线、真实支付、真机验收代签。

## 页面和接口

推荐页顶部标题、搜索、横向简单分类、双列商品；详情 3–5 图原生 swiper、价格与份额、底部下单面板。个人、地址、订单、人工客服、工单、消息沿用实际交互并统一视觉。新增智能客服页面和入口，明显标记 AI；加载、空数据、失败、登录过期各自有准确反馈。不得虚构促销、销量或交易事实。

API 保持 `{data,requestId}` 包络。商品 GET `/api/mini/v1/products` 新增 keyword（trim 后≤60字符）及 category（fruit/snack/drink/other，可省略）；二者 AND，仅上架，page≥1，pageSize≤50。商品读视图与后台写入新增可选 category，旧客户端兼容。金额仍整数分。

地址继续现有 AddressSaveRequest；定位为本地表单辅助，不新增地理位置服务。智能客服 GET `/api/mini/v1/ai-support/messages?before=ISO&pageSize=20`、POST `/api/mini/v1/ai-support/messages` `{clientMessageId:UUID,text:1..1000字符}`，用户 Bearer；只读本人消息，升序呈现最近页，nextBefore 可分页。发送返回 `{turn:{id,clientMessageId,text,reply,status,createdAt},replayed}`。未配置503 AI_NOT_CONFIGURED，异常502 AI_UNAVAILABLE，超时504 AI_TIMEOUT，进行中409 AI_BUSY，同键异文409 IDEMPOTENCY_CONFLICT，校验400。并发数据库租约、同用户每分钟最多10次新轮次，默认30秒模型超时，最多20条/8000字符历史，文本输出≤4000字。无管理员访问其他人 AI 历史接口。

## 验收

- AC01：推荐页搜索/分类请求实际后端，正确过滤总数与分页，旧请求不能覆盖新筛选；空、失败、更多加载反馈可操作。
- AC02：10 个独立演示商品，每个3张不同真实网络照片，经现有媒体上传与商品用例保存；记录来源，种子重跑不重复，不覆盖既有商品；生产禁止演示导入。
- AC03：详情自动轮播、手动滑动、图片预览与按压反馈有效，隐藏停止轮播；下单传实际 productId，禁止伪造成功。
- AC04：Given用户主动定位，When选点成功，Then只填详细地址并提示确认省市区；拒绝/取消/不可用不覆盖已有内容，能手填。未确认地区不得误用默认广东地址。
- AC05：Given登录用户，When发送文本，Then由项目内真实 Pi Agent 管理文字历史；无工具、文件、命令或业务修改能力；提示 AI 回复需要人工核实，不承诺已退款。
- AC06：身份隔离、幂等、同键异文、并发、限流、超时、异常及重启恢复有自动验证；密钥和历史不进入日志/客户端，关闭配置不影响人工客服。
- AC07：所有既有页面主要入口可达，系统字体/安全区/可点区域、加载和错误反馈一致，安卓真机验证单独记录。
- AC08：整体专项通过后全量通过；有环境缺口明确待验，不把 Mock 模型与模拟微信写成真实渠道成功。
