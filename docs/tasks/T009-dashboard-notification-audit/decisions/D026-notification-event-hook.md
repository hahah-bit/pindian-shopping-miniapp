# D026 通知事件接入方式

- **状态**：设计结论（2026-10-02）。
- **决策**：采用 **Worker 扫描式事件补抓**（复用 D012「幂等重扫」模式）：新任务按幂等键扫描 `refunds.status='succeeded'`、`groups.status='success'` 中缺失通知的事实并补建通知+初始投递。**不**修改 T006 支付确认/退款确认用例、不修改 T008 会话用例。
- **理由**：T006 四轮修复后的确认事务是全系统风险最高的代码，内联通知写入需要重开并发回归；扫描式与履约生成任务同构，最终一致（延迟≈扫描间隔），幂等键唯一约束兜底双实例并发。
- **代价**：通知创建非实时（秒级）；一致性延迟与补偿（下轮重扫）在 ddd §3 声明。
