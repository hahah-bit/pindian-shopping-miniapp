# T007 分份履约与独立发货

- **编号**：T007（唯一；子功能 F026–F030，已核对无冲突：现有子功能至 F025，任务至 T006，迁移至 0015）。
- **目标**：拼单成功后为每位有效参与用户生成独立履约单，按购买份额精确分配商品数量（整数克，守恒可证明）；管理员分别发货（快递公司+运单）、部分发货、补发、导出发货单；用户查看本人履约进度并确认收货。一个用户发货不代表整组完成；履约事实与订单/支付/组状态投影分离。
- **主领域**：Fulfillment（分份履约）；**协作领域**：GroupBuying（成功组事实）、Ordering（有效订单与快照）、IdentityAccess（用户昵称/权限）、Audit（操作审计）。
- **前置**：T004（组/订单/快照）、T006（支付闭环、组成功事实、Worker 模式）。**不实施**：视觉改造、客服、售后工单、看板、物流渠道对接（运单为后台录入）。
- **当前状态**：实现中。
- **阻塞项**：无（业务歧义已按建议方案固化为 D011–D015，**未经用户逐项确认，标记"建议方案、可后改"**；分配策略与生成触发已隔离在可替换单元）。

## 工作决策（建议方案，待用户确认）

| 编号 | 议题 | 决策（建议方案） | 状态 |
| --- | --- | --- | --- |
| D011 | 数量精度/舍入/尾差 | 整数**克**为最小存储与计算单位（1 斤 = 500 g）；分配 base_i = floor(totalG × units_i / 60)，余数 R = totalG − Σbase_i 按**订单创建顺序**给前 R 单各 +1 g；Σ 恒等于 totalG（守恒可证明）；展示转斤 3 位小数。不照搬货币尾差、无损耗 | 建议方案 |
| D012 | 生成时机 | Worker 任务自动生成：扫描「success 且尚无履约单」的组，逐单创建；幂等（order_id 唯一）、失败可重试、重启恢复（D010 单 Worker 循环模式，任务 5→6 个） | 建议方案 |
| D013 | 包裹粒度 | 一履约单**多包裹**：常规一单一件；部分发货=包裹数量之和小于分配数量；补发=追加 `is_reissue` 包裹（需原因+审计），不计入发货进度 | 建议方案 |
| D014 | 完成依据 | Σ非补发包裹数量 = 分配数量 → `shipped`；用户小程序确认收货**或**管理员手动标记 → `completed`（completed_by 区分）；不自动超时完成 | 建议方案 |
| D015 | 改址与补发权限 | 用户不可改址（订单快照不可变）；管理员可在发货前修改收货快照（版本号+1、写审计、履约单维度生效）；发货后收货信息锁定；补发为 order:manage + 必填原因 + 审计 | 建议方案 |
