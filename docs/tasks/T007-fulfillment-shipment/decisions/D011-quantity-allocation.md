# D-011 履约数量精度、单位与尾差分配

> **状态：已确认**（用户 2026-10-01 通过方案选项确认："重量克化+计数整件"）。
> 单位注册表（独立审查 R01 后扩展，2026-10-01）：
> - **重量单位**按克换算：斤=500g、千克/kg=1000g、克/g=1、两=50g（数量允许小数，换算结果必须为整数克，否则该商品不可履约）；
> - **计数单位**按整件：个/件/只/盒/箱/瓶/包/袋/桶/罐/台/张/支/枚 等（数量必须为整数，小数→不可履约）；
> - **未知/其他单位**：生成时拒绝并留痕（不静默），不缩减 T002 1-10 字自由单位商品的上架范围；
> - 展示回**原快照单位**（克→斤 3 位小数、计数→整数件等）；历史组快照与历史交易不回写。

## 决策

整数**最小单位**（重量=克、计数=件）为履约数量的存储与计算单位：
- 组整件最小单位数 `totalU = convert(whole_quantity, unit)`（换算非整数 → 该组生成失败并留痕，属商品配置错误）。
- 每单分配：`base_i = floor(totalU × units_i / 60)`；余数 `R = totalU − Σbase_i`（`0 ≤ R < 订单数`）；按**订单创建顺序**给前 R 单各 +1。
- 守恒证明：Σ分配 = Σbase_i + R = totalU（严格守恒，无损耗、无浮点）。
- 展示：按原单位换算文本（重量单位 → 3 位小数；计数单位 → 整数）。

## 备选与理由

- 毫克：精度冗余、数值过大（普通生鲜 ±0.5g 无业务意义）。
- 斤 3 位小数直接分配 + 尾差末单：与货币尾差同构，违反"不照搬货币规则"约束；0.001 斤粒度≠均匀克数。
- 原单位整数份：无法处理 10 斤 × 1/3 的不可整除问题。

## 影响与回退

分配策略隔离在纯函数（F026 `allocateQuantity` + 单位注册表 `toMinimalUnits`/`formatQuantity`）；若用户后续改选，仅替换该层。
