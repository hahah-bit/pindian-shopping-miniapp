# D-011 履约数量精度与尾差分配（建议方案，待用户确认）

## 决策

整数**克**为履约数量的最小存储与计算单位（1 斤 = 500 g）：
- 组整件克数 `totalG = whole_quantity × 500`（whole_quantity ≤ 3 位小数；乘积非整数克 → 该组生成失败并留痕，属商品配置错误）。
- 每单分配：`base_i = floor(totalG × units_i / 60)`；余数 `R = totalG − Σbase_i`（`0 ≤ R < 订单数`）；按**订单创建顺序**给前 R 单各 +1 g。
- 守恒证明：Σ分配 = Σbase_i + R = totalG（严格守恒，无损耗、无浮点）。
- 展示：`allocatedQuantityText` = 克 → 斤 3 位小数 half-up（1.667 斤）。

## 备选与理由

- 毫克：精度冗余、数值过大（普通生鲜 ±0.5g 无业务意义）。
- 斤 3 位小数直接分配 + 尾差末单：与货币尾差同构，违反"不照搬货币规则"约束；0.001 斤粒度≠均匀克数。

## 影响与回退

分配策略隔离在纯函数 `QuantityAllocator`（F026）；若用户后续改选，仅替换该函数与展示换算。
